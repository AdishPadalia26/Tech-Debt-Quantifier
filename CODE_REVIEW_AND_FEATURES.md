#### C1. In-memory `jobs` dict — every restart drops in-flight analyses
**File:** `backend/main.py:66-67`  
**Priority:** CRITICAL

Module-level dicts hold ALL job state and result cache. A restart loses every running job; users polling get phantom 404s. Also means you can never scale past one worker.

```python
# BEFORE (main.py:66)
jobs: dict[str, Any] = {}
_result_cache: dict[str, tuple[dict[str, Any], datetime]] = {}
```

```python
# AFTER — use Redis (already in docker-compose.yml)
import json
from redis import Redis
_redis = Redis.from_url(os.getenv("REDIS_URL", "redis://localhost:6379"), decode_responses=True)

def _job_key(job_id: str) -> str: return f"job:{job_id}"

def set_job(job_id: str, data: dict) -> None:
    _redis.set(_job_key(job_id), json.dumps(data, default=str), ex=3600)

def get_job(job_id: str) -> dict | None:
    raw = _redis.get(_job_key(job_id))
    return json.loads(raw) if raw else None

def update_job(job_id: str, **fields) -> None:
    data = get_job(job_id) or {}
    data.update(fields)
    set_job(job_id, data)
```
Then replace all `jobs[job_id]` reads/writes with `get_job()` / `update_job()`. Redis is already a dependency — zero new infra.

#### M10. `setTimeout` polling duplicated in 3 frontend files
**Files:** `page.tsx`, `portfolio/page.tsx`, `lib/api.ts`

```typescript
// frontend/src/hooks/usePolling.ts
export function usePolling<T>(
  fn: () => Promise<T>,
  shouldStop: (data: T) => boolean,
  intervalMs = 1500
) {
  const [data, setData] = useState<T | null>(null);
  useEffect(() => {
    let active = true;
    let timer: ReturnType<typeof setTimeout>;
    const tick = async () => {
      if (!active) return;
      const result = await fn();
      if (!active) return;
      setData(result);
      if (!shouldStop(result)) timer = setTimeout(tick, intervalMs);
    };
    tick();
    return () => { active = false; clearTimeout(timer); };
  }, []);
  return data;
}
```

## PART 2: NEW FEATURES

### F1. PR Diff Mode — analyse only changed files in a pull request ⭐
**Effort:** 1-2 days | **Libs:** none new (gitpython, httpx, cost_estimator all exist)

**What:** Paste a GitHub PR URL → run debt analysis only on `git diff main..HEAD`. Returns "this PR adds $X of debt / removes $Y."

**Why:** Today every analysis runs the whole repo (45-90s). PR review needs 5-second feedback on what *this change* costs. This is the path into CI pipelines.

**How to implement:**
1. New route `POST /analyze/pr` accepting `{ pr_url }`. Parse `github.com/owner/repo/pull/N` → call GitHub API `GET /repos/{owner}/{repo}/pulls/{N}/files`.
2. New `tools/diff_analyzer.py`: filter `tools/static_analysis.py` output to only PR-touched files.
3. Reuse `cost_estimator.estimate_total_cost()` on the filtered set.
4. Comparison mode: run on `base` branch, diff the two totals → "this PR: +$1,240 debt across 3 files."
5. Frontend: `app/pr/[...slug]/page.tsx` with a compact diff view.
